**1. 실행 환경과 과거 결과 재현**

로컬 Git 커밋 `20f9da2`를 별도 폴더에 복원했다. 모델 manifest에 기록된 게임 원본·밸런스·생성 엔진·나무·브리지·환경의 SHA-256 6개가 모두 일치했다. 기존 모델과 관측 정규화 파일의 SHA-256도 보관된 provenance와 일치했다.

Python 3.13.16과 PyTorch 2.14.1+cpu, NumPy 2.5.4, Gymnasium 1.4.0, Stable-Baselines3 2.9.0, sb3-contrib 2.9.0을 작업 폴더에 준비했다. Node는 현재 제공되는 24.22.1을 사용했다. 과거 문서의 Node 24.20.0과 버전 차이가 있었지만, 저장 PPO와 규칙 봇 모두 기존 보고서의 모든 집계 및 에피소드 필드가 정확히 재현됐다.

과거 엔진과 현재 로컬 엔진에서 각각 Python 테스트 15개와 Node 브리지·마스크·보상 테스트가 통과했다. 마스크 테스트는 5,709개 판정을 검사했다. 현재 엔진 복사본의 초기 테스트에서는 `starter.json` 복사 누락으로 실패했으며, 해당 설정을 복사한 뒤 전체 테스트가 통과했다. Gymnasium은 기존과 같이 관측 상한 infinity에 대한 경고를 출력했다.

**3. 행동 진단과 한 요소 실험**

개발 결과에서 기존 최선 마스킹 모델이 두 새 후보보다 좋아 이 모델을 진단 대상으로 선택했다. seed 94000의 시작 행동은 궁수 6번 자리 건설, 궁수 강화 두 번, 벌목 인구 고용이었다. 첫 누수는 1웨이브의 약 69게임초에 발생했다. 규칙 봇은 궁수 강화와 성 강화 후 3번 자리부터 건설했다.

대기 중 합법적인 건설 행동이 있는 경우도 확인됐지만, 그때 규칙 봇이 실제로 건설을 선택하는 경우는 진단 10판에서 0번이었다. 따라서 대기 비율만으로 자원을 남기고 건설을 회피한다고 판단할 수 없다. 준비했던 ‘첫 건설을 규칙 봇에 맞춰 개입’ 조건도 별도 20판에서 실제 행동을 한 번도 바꾸지 못했고 결과가 동일했다. 이 무효과 진단도 `opening-diagnostic.json`에 보존했다.

다음 실험은 모델의 첫 건설 위치만 6번에서 3번으로 바꿨다. 건설 시각 0초와 궁수 종류는 유지하고, 이후에는 같은 모델을 실행했다. 개발 96000–96009와 새 검증 99000–99019를 사용했다. 이 모델은 원래 모든 해당 에피소드에서 0초에 궁수 6번 자리 건설을 선택했다.

개발 10판 모두와 새 검증 20판 모두에서 완료 웨이브가 증가했다. 새 검증은 18판에서 +1, 2판에서 +3이었다. 검증의 누수 비율은 집계한 실제 완료 웨이브 수 기준으로 2.38→0.755회/웨이브였다. 생존 시간은 소폭 줄어 모든 지표가 개선된 것은 아니다. 최종 HP는 모두 0이었다.

이는 추론 시 첫 행동에 규칙을 적용한 효과이며 PPO 가중치는 갱신하지 않았다. 현재 게임 엔진에서 같은 효과가 유지되는지는 이번 위치 실험의 범위에 포함되지 않았다. 개발과 검증 시드를 분리했지만 학습된 정책 하나와 이 위치 개입에 대한 결과다.
