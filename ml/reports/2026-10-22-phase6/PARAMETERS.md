# 파라미터의 근거와 확대 예상

이번 확인 환경: AMD Ryzen 5 PRO 4650U with Radeon Graphics, 논리 CPU 12,
Windows에서 사용 가능한 총 물리 메모리 약15.2GiB, 현재 CPU 전용 torch(CUDA 불가).
이 정보는 런타임/레지스트리를 읽어 확인했으며 학습 설정을 자동 탐색한 결과가 아니다.

파라미터는 망의 학습 가중치와 사람이 정하는 하이퍼파라미터를 구분해야 한다.
38,702개 가중치는 학습으로 조정되지만 위 학습률/할인율/배치 등은 사람이 정한 값이다.
현재는 하드웨어 기반 최적화도 게임 전용 전체 탐색도 하지 않았다.

순서는 보상/목표 의미 수정 → 같은 예산 비교 → 여러 학습 seed 재검증 → 수집 길이·망 크기 순이 적절하다.
표의 확대 효과는 예측이며 이번에는 망/배치/epoch/스레드를 늘려 성능을 실험한 것이 아니다.

설치 SB32.9.0 PPO.__init__의 signature로 기본값을 직접 확인했다.
[공식 PPO 문서](https://stable-baselines3.readthedocs.io/en/v2.9.0/modules/ppo.html),
[공식 MaskablePPO 문서](https://sb3-contrib.readthedocs.io/en/master/modules/ppo_mask.html).

## 실패 행동의 정확한 정의

실제로 전달된 행동의 action_result에 error가 있으면 실패 행동이다.
예: 금 부족 건설/고용, 크리스탈 부족 강화, 문명 잠금, 점유된 터 건설,
포탑 없는 터 판매, 최대 인원 초과, 연구/물약 조건 미충족, 동시2웨이브 제한 초과.
20목표 모드에는 목표를 넘는 수동 웨이브 시작을 거절하는 학습 전용 제약도 포함한다.
비율 = error가 반환된 step수 / 전체 step수이며 각 실패는-.05다.

대기, 위치가 나쁜 포탑, 불리한 판매, 성 함락, 목표 달성 실패는 이 지표의 실패 행동이 아니다.
행동 ID 자체가 범위를 벗어나면 Python 예외로 처리하며 정상 rollout의 실패 횟수와 구분한다.
마스크0%는 규칙상 합법 선택을 뜻하며 전략적으로 똑똑함이나20웨이브 성공을 보장하지 않는다.
