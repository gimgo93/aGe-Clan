이는 예측 모델 변경이나 새 패치 채택 조건의 변경이 아니다.

## 단계와 통과 기준

1. 현재 실행 완료: 4,890판 수집, 개발 비교 60판, 새 시드 최종 비교 50판.
   CPU 수치 연산 1스레드, 하루 최대 5,000판, 실행 최대 6시간. 중복 실행 금지.
2. 완료 후 `audit` 실행: 전략별 MAE, 상수 기준 MAE, 설정별 평균 오차 개선,
   1,000회 설정 단위 bootstrap 구간, 실패 행동·시간 제한 종료를 확인한다.
   독립 설정이 10개 미만이면 구간을 제시하지 않는다. 구간은 사람 실력이나 예측값 신뢰구간이 아니다.
3. 다음 모델 실험: 동일 고정 데이터에서 ridge 정규화만 먼저 비교한다.
   모델 크기/정책/보상/게임 수치를 동시에 바꾸지 않는다. 현재 모델을 기준으로 보존한다.
   설정 단위 내부 검증으로 설정을 선택하고, 반복 선택에 사용하지 않은 외부 검증 세트에서 판단한다.
   데이터 부족이나 상수 기준보다 나쁜 경우 추천을 계속 보류한다.
4. 후보 검증: 예측 순위만으로 패치하지 않는다. 동일 정책·같은 시드 대조 후
   새 시드에서 재검증한다. 20/30/40 도달, HP·처치·누수·시설 이용·실패 행동률을 함께 본다.
5. 범위 확대: 검증력이 확보된 뒤 물약 비용/효과, 경제, 포탑 조합을 한 요소씩 확장한다.
   첫판10–15 / 2–3판후20 / 중수30 / 40부터 고급 전략이라는 목표는
   사람 플레이 자료로 별도 보정해야 한다. 고정 정책을 사람 숙련도로 간주하지 않는다.

궁수 방어 적/궁수 저항/15웨이브 강제 상한은 도입하지 않는다.
일일 원시 데이터와 모델은 runs에만 보존하고 Git에는 소스·테스트·요약만 올린다.

## 사전 등록: 정규화 비교 1회

가설: 고정 64개 tanh 특징과 5개 bootstrap 모델을 유지하고 ridge만 0.5/2/8로 비교하면
과도한 정규화 또는 과적합을 줄일 수 있다. 내부 3분할에서 설정 단위 MAE로 선택한다.
설정 해시 정렬의 매 5번째 설정을 외부 검증으로 고정하고 선택에 사용하지 않는다.
최종 선택 모델과 ridge2 대조를 동일 외부 설정에서 비교한다. 외부 세트는 이 비교 내에서만
선택에 미사용이며 완전히 새로운 게임 시드의 대체가 아니다. 최소 30개 설정이 필요하다.
완료된 실행에서만 수행하고 실행 중 원시 기록, agent, model.py는 변경하지 않는다.
최초 비교 결과도 보존하며 외부 결과를 보고 반복 조정하려면 별도 검증 계획이 필요하다.

## 40 난이도 소폭 상승 / 50 도전 목표 — 최신 사용자 지시

게임은 무한 모드지만 현재 ML worker는40에서 평가를 종료하고 예측 모델도40으로 정규화한다.
기존 실행은 완주·보존하고 50평가 데이터/모델과 섞지 않는다. 신규 frontier50은 별도 평가기다.
첫 후보는36웨이브부터 적HP1.05배, 종류·속도·초반 규칙은 그대로다.
40달성 난이도가 실제로 증가하는지,50은 고급 정책으로 가능한지 모두 미검증이다.
1초 대0.2초 판단 주기 비교와 물약/경제 제외 대조를 분리한다.0.2초는 완벽한 최적 타이밍의 증명이 아니다.
먼저 현재수치에서50 성공 정책을 찾은 뒤 작은 난이도 후보를 비교한다. 모두50실패하면
더 어렵게 하는 후보를 채택하지 않는다. 배치/경제/물약 정책을 하나씩 개선하고 동일 대조로 재검증한다.
개발시드3개와 새확인시드5개는 frontier50-plan.json에 사전 고정한다.
현재5천판 예산에 추가 배치를 얹지 않으며 다음 일일 예산 안에 별도 배분해야 한다.
50목표 ML을 만들 때 정규화50·target metadata·엔진/정책/평가설정 hash를 별도 기록하고 기존40모델을 보존한다.
운영배포/자동패치 허가는 아니며 최종 후보는 근거와 함께 검토한다.
