# aGe Clan 운영 구조 · 2026-10-21

## 1. Google 연동

Google Identity Services의 로그인 버튼 → Google ID 토큰 → 게임 계정 API의 서명·발급자·클라이언트 ID·만료·일회성 nonce 검사 → 게임 전용 세션 쿠키 발급 순서입니다. Google 계정 식별자 `sub`를 해시해 내부 계정과 연결합니다. 비밀번호는 게임에 전달되지 않으며 이메일·실명·Google 프로필 사진은 게임 계정 DB에 저장하지 않습니다.

같은 Google 계정으로 로그인하면 군주 이름·문장·허용된 설정·서버 판정 성장 기록·업적·최고 방어 기록을 불러옵니다. 설정은 버전 번호로 동시 수정 충돌을 알립니다. 전체 전투를 원하는 시점에서 이어 하는 범용 클라우드 저장이나 여러 기기의 동시 조종 기능은 아닙니다. 세션은 기기별이며 로그아웃은 해당 세션, 계정 삭제는 모든 세션과 계정 기록에 적용됩니다.

**업적 조회·신규 달성 및 랭킹 조회·등록은 로그인 계정에 한정합니다.** 게스트도 플레이할 수 있으나 새 게스트 랭킹은 저장하지 않습니다. 이전 익명 랭킹은 공개 목록에서 제외되고, 소유 세션으로 로그인하면 기존 서버 기록을 그 계정으로 이전할 수 있습니다. 이전 브라우저 업적 가져오기는 로그인 후에만 가능하며 미검증으로 구분합니다.

실제 사용자 Google 로그인과 두 독립 세션의 자동 검사는 확인했습니다. 실제 휴대폰·PC 사이의 장시간 동기화 시험은 남아 있습니다. [Google ID 토큰 검증 문서](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token)

## 2. 현재 서버 수용량과 최적화

방 정원은 5명입니다. 분리된 환경에서 최대 **20명·4개 방, 단계별 30초**를 시험해 오류·명령 오류·연결 종료 0건, 후반 명령 확인 p95 약207ms를 확인했습니다. 이는 서버 전체의 최대 동접 상한이나 24시간 안정 운영을 보장하지 않습니다. 확대 부하 시험은 요청에 따라 중단했습니다.

현재 최적화: 방별 메모리에서 서버 판정, WebSocket 변경분 전송, 관전 대상만 상세 데이터 전송, 클라이언트 이동 보간, 명령 중복 방지, 약2초 복구 체크포인트, 약5초 방 색인·성장 기록 저장입니다. 매 전투 명령마다 D1 왕복을 기다리지 않습니다. 강제 종료 시 마지막 복구 저장 이후 진행이 일부 되돌아갈 수 있습니다.

추가 가능 항목은 장시간 시험으로 병목을 확인한 뒤 우선순위를 정해야 합니다. 후보는 계정 조회·색인 쓰기 합치기, 사람이 없는 방의 실행·저장 중지, 적 타깃 탐색 비용 절감, 상태 직렬화와 변경분 크기 축소, 혼잡 시 전송 빈도 조정입니다. 빈도 축소는 부드러움·복구 수준과 맞바꾸므로 이번에는 임의로 변경하지 않았습니다.

20명 장시간 → 50/100/200명 단계별 → 실제 국내망·휴대폰 시험의 조건과 중단 기준은 [측정 보고서](CAPACITY_2026-10-20.md)에 있습니다. 무료 한도는 별도 제약입니다. 현재의 전투 타이머는 방을 계속 활성 상태로 유지하므로 20명 상시 운영이 무료 한도에 들어간다고 보장할 수 없습니다. [Cloudflare 무료 한도](https://developers.cloudflare.com/durable-objects/platform/pricing/)

## 3. 도메인

`ageclan.com`은 Cloudflare Registrar에서 구입했고 Cloudflare DNS가 주소를 관리합니다. 루트 A 레코드와 `www` CNAME이 Sites 호스팅 대상으로 연결되며 인증 TXT가 HTTPS 인증을 지원합니다. 연결 당시 DNS only로 설정했고 Sites의 사용자 지정 도메인·TLS가 활성화됐습니다. 인증 TXT는 임의로 삭제하지 마세요.

사용자가 `https://ageclan.com/game/`에 접속하면 Sites가 게임 화면과 같은 출처의 API 입구를 제공합니다. 원래 `chatgpt.site` 주소도 유지합니다. 도메인 소유와 게임 호스팅·방 서버 운영은 서로 다른 역할입니다. 도메인 연간 갱신은 별도로 관리합니다.

## 4. DB와 통신

- **운영 D1 `age-clan-pvp-db`:** 방 검색·입장용 색인/스냅샷, 계정·세션·로그인 nonce, 성장 기록·랭킹. 게임 코드만 바인딩으로 접근하며 브라우저에 DB 자격 증명을 주지 않습니다.
- **방별 Durable Object SQLite 저장소:** 메모리의 권위 있는 전투 상태를 복구하기 위한 체크포인트. D1과 별도 저장소입니다.
- **Sites D1:** 기존 사이트 기능과 의견 보내기 등 Sites 쪽 경로에 사용합니다. 외부 대전 서버 D1과 혼동하면 안 됩니다.
- **브라우저 저장소:** 게스트 프로필·설정·예전 로컬 기록. 주소별로 분리되며 로그인만으로 다른 주소의 로컬 저장소를 읽지는 못합니다.

초기 입장·계정 저장 등은 HTTPS JSON 요청, 전투 중 상태·명령은 WebSocket을 사용합니다. 브라우저 → Sites API/소켓 → 비밀키로 인증된 외부 Worker → 방별 Durable Object 순서입니다. 서버가 자원·피해·승패를 결정합니다. 서버 비밀키는 브라우저 번들에 포함하지 않습니다.

DB 관리는 Cloudflare 대시보드 D1에서 조회하거나 Wrangler로 수행합니다. 스키마는 `db/schema.ts`, 변경 이력은 `drizzle/`이며 배포 시 migration을 적용합니다. 운영 자료 수정·삭제 전에는 대상 DB와 복구 방법을 확인해야 합니다. 사용자 계정 삭제는 게임의 계정 메뉴에서 제공합니다. 자동 외부 백업·운영 경보를 완성했다고 주장할 수는 없으며 장기 운영을 위해 별도 구성·복원 훈련이 필요합니다.

## 5. 서버 구성

고정 PC 한 대를 서버로 여는 방식이 아닌 Cloudflare의 서버리스 구조입니다.

1. Sites: HTML/JS/이미지, 같은 출처의 API·소켓 입구, HTTPS 사용자 도메인.
2. 사용자 Cloudflare 계정의 `age-clan-pvp` Worker: 요청 인증, 로그인·방 찾기, 방 라우팅.
3. `ClanRoom` Durable Object: 방당 하나의 순차 처리 주체. 최대5명, 전투 진행·명령 판정·상태 전송·복구 저장.
4. D1: 계정·기록·검색 색인 등 지속 데이터.

방이 여러 개면 서로 다른 객체로 분산되지만 계정의 CPU·요청·DB·실행 시간 한도는 공유합니다. 방당 5명이 서버 전체 5명 제한을 뜻하지는 않습니다.

## 6. Google Cloud가 제공하는 것

현재 Google Cloud 프로젝트에는 aGe Clan의 OAuth/Google Auth Platform 설정이 있습니다. 앱 이름, 동의 화면, 공개 대상, 허용 웹 출처, 웹 클라이언트 ID를 관리하며 Google Identity Services가 사용자 로그인과 ID 토큰 발급을 제공합니다.

**Google Cloud에서 게임 전투 서버·게임 DB·도메인 호스팅을 제공받고 있는 구성은 아닙니다.** 현재 구성에는 Google Compute Engine, Cloud Run, Firebase DB, 머신러닝 학습 서버가 연결돼 있지 않습니다. 게임 실행과 DB는 위의 Cloudflare/Sites 구성입니다. 로그인 연동을 위해 Google 유료 체험이나 결제 플랜을 등록하지 않았습니다.
