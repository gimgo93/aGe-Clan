# aGe Clan 초기 진입 최적화

기준: GitHub main `2a1b916`. 작업 브랜치 `codex/startup-performance`.
현재 운영 사이트를 변경하거나 도메인/DNS를 이동하지 않았다. 이 문서는 코드 검사·파일 크기·소수 네트워크 표본과 실제 확인한 클라우드 설정을 구분한다.

## 구조와 원인

브라우저 → Sites(HTML/JS/이미지, 같은 출처의 API 입구) → 인증된 Cloudflare `age-clan-pvp` Worker → 방별 `ClanRoom` Durable Object / D1.

- 기존 `renderer.load()`는 20개 이미지가 모두 준비되어야 로딩 덮개를 숨겼다. 광산/광장 이미지 하나가 지연돼도 시작 화면을 막았다.
- 사용되지 않는 `ballista`, `ballista-arm`, `ballista-new`도 시작 시 내려받았다.
- `GameApp` 공개와 계정 상태 확인이 전체 이미지 준비 뒤에 시작됐다.
- 로비가 전장을 가리고 있어도 매 프레임 전장 렌더링과 HUD 갱신을 수행했다.
- 로그인 상태 확인 중 계정·성장·랭킹 조회와 조건부 UPDATE를 항상 순차 대기했다. 창 포커스가 돌아올 때 중복 상태 확인도 가능했다.
- WebSocket 전투는 이미 방 메모리에서 진행하며, 복구 저장 약 2초/디렉터리 약 5초 구조다. 이번 초기 진입 문제만으로 전투 tick이나 복구 주기를 변경할 근거는 없다.

## 소수 네트워크 표본 (변경 전)

같은 PC에서 URL별 한 번 순차 요청. 브라우저 FCP/LCP/실사용 핑의 평균이 아니다.

| 경로 | 응답 헤더까지 | 전체 수신 | 바이트 |
|---|---:|---:|---:|
| `/game/` | 2306ms | 2337ms | 28,981 |
| 제목 배경 WebP | 1341ms | 1615ms | 335,874 |
| `grassland.webp` | 322ms | 937ms | 2,660,730 |
| `/api/clan` GET | 339ms | 342ms | 112 |

HTML은 `max-age=0, must-revalidate`, 이미지 응답은 `max-age=14400, must-revalidate`. API는 `no-store`로 유지한다. 계정 응답을 공용 캐시에 넣지 않는다.

## 구현한 단계

| 단계 | 변경 | 검증/상태 |
|---|---|---|
| 1. 첫 화면 | 제목을 먼저 표시, 준비 진행 표시, 실패 시 재시도, 게임 버튼은 준비 완료까지 잠금 | 코드 검사 완료, 실제 화면 검사 대기 |
| 2. 자산 | 미사용 이미지 3개 제외, 9개 PNG를 같은 크기/투명도의 무손실 WebP로 변환 | 게임 준비 자산 25,805,645 → 19,192,554바이트, 25.6% 감소 |
| 3. 다운로드 | 최대 4개 동시 로드, 비동기 decode, 이미지별 20초 제한, 성공 자산 재사용 | 동시성·오류·시간초과·재시도 검사 통과 |
| 4. 로비 | 가려진 전장/주기적 HUD 렌더링 중지, 걷기 자산은 유휴 시점 또는 제한시간 뒤 요청 | 기존 게임/음향 회귀 검사 통과 |
| 5. 계정 클라이언트 | 이미지 로딩 전에 설정/계정 API 사용 가능, 진행 중 조회 합치기, 포커스 복귀 조회 15초 간격 제한 | 수동 새로고침은 제한하지 않음 |
| 6. 계정 DB | 계정·성장·랭킹을 LEFT JOIN으로 조회, 과거 랭킹 소유권이 비어 있을 때만 UPDATE | 로그인·동기화·삭제·관리자 표시 테스트 통과. 일반 status는 세션 확인+계정 통합 SELECT 2회, 랭킹 UPDATE 0회 |

정상 계정의 계정-view 부분은 기존 4회 SQL 호출에서 1회로 감소한다. 요청 제한·세션·nonce·JWT 검증은 그대로이며, API 전체가 SQL 1회라는 뜻은 아니다.

## 클라우드 확인

- Wrangler OAuth 로그인, Worker 쓰기/라우트/D1 권한 확인.
- 운영 Worker 버전 `8a0543ec-2c9f-4b0b-896a-a596d86a72f3`(조회 시점).
- `CLAN_ROOMS` Durable Object, 게임 D1 `age-clan-pvp-db`, Google client 설정, 서버 인증·관리자 비밀키의 이름 존재 확인. 비밀값을 읽거나 변경하지 않았다.
- D1에서 EXPLAIN QUERY PLAN만 실행: 계정·성장·랭킹 모두 ID 인덱스 사용. 실제 계정 데이터 조회/수정 없이 변경 행 0. `0.31ms`는 EXPLAIN 자체 실행 시간이며 로그인 지연 측정치가 아니다.
- `/app`의 별도 Worker/DB는 작업 대상에서 제외.

## 남은 단계와 배포 조건

1. 브라우저 권한이 도구에 반영되면 느린 네트워크/정상 네트워크로 각각 최초·재방문 5회 측정. `age-lobby-ready`, `age-game-ready` 성능 표식과 네트워크 타이밍 수집. 초기 메뉴·모바일 배치·재시도·혼자하기·방 복귀 검증.
2. Sites 연결 복구: 현재 기존 프로젝트 조회는 NOT_FOUND. 새 프로젝트/DNS 변경으로 우회하지 않았다. 화면 코드는 이 연결 또는 별도로 검증한 새 배포 구성이 필요하다.
3. 백엔드 배포 전 운영 Worker 소스와 현재 GitHub 백엔드의 대응을 확인하고 운영 바인딩/환경변수를 보존한 배포 파일을 준비한다. 계정·두 기기 동기화·대전 재접속 smoke test 후 승격한다. Worker 인증은 살아 있지만 웹 화면 배포 권한과는 별개다.
4. 서버 성능은 2~4명 비공개 시험방에서 RTT, 명령 응답, 스냅샷 간격, tick 지연, 저장 지연을 먼저 수집한다. 확장 부하 시험은 사용량/중단 기준을 정한 후 진행한다. 이번에는 운영 부하 시험을 하지 않았다.
5. 첫 HTML의 응답 지연이 반복된다면 Sites 전달 경로와 캐시를 조사한다. 정적 프런트엔드 Cloudflare 이전은 로그인/소켓/쿠키/인증서/도메인 검증을 포함한 별도 배포 단계다.

## 실행한 검사

`check-startup`, `check-accounts`, `check-account-badges`, `check-ux-refinement`, `check-ui-audio`, `check-pvp`, `check-pvp-gateway`, 프레임워크 production build 통과.

브라우저 활성화 응답 후 도구 세션까지 초기화했지만 계속 비활성화로 반환돼 실제 프레임/화면 검증은 미완료. 파일 용량 감소를 동일 비율의 로딩 시간 감소로 주장하지 않는다. 변경은 운영 배포 전 상태다.
