# 4인 PvP·국경 지도·관전 변경 — 브라우저 검증 대기

## 승인 경계

사용자가 세로 시작 메뉴 제안을 거절했다. 새 세로 메뉴 CSS 연결을 제거하고 기존 하단 메뉴 배치로 되돌렸다. 친구와 대전 및 방 만들기/코드 입장 통합은 유지했다. 이전 승인 요청의 42915c5는 운영 배포하지 않았으며, 이번 변경도 아직 push·Sites 저장·프런트/백엔드 배포하지 않았다. 실제 브라우저 화면을 보여준 뒤 사용자 승인을 받아야 한다. 현재 운영은 v567 / Sites 58 기준이다.

## 구현

- 상단 표기를 문명 타워 디펜스로 변경. 중복 aGe Clan 텍스트 제목을 제거하고 그대의 문명과 함께하라를 메인 제목으로 올렸다. 구석기·신석기·청동기·철기·현대는 유지했다. 계정 영역은 밝은 반투명 색과 짙은 글자/아이콘으로 배경과 맞췄다.
- 새로운 PvP 방 정원은 4명, 친구 방은 2~4명이다. PvP 시작 시 서부·남부·북부·동부 국경지대를 중복 없이 배정하고 체크포인트/재접속 후 유지한다. 혼자하기는 사용자가 오타 수정을 확인한 중앙 국경지대다. 기존 5인 진행 방은 참가자를 강제 퇴장시키지 않고 예외로 유지한다.
- 기존 상대 상태 목록·별도 관전 창을 제거했다. 지도 아이콘으로 직접 제작한 SVG 두루마리 지도를 열고, 지역 버튼을 누르면 주 화면의 선택 지역으로 전환한다. 본인 국경 복귀 버튼을 제공한다.
- 관전은 별도의 watchGame 상태를 사용하며 자기 게임 상태를 덮어쓰지 않는다. 주 캔버스의 렌더러만 선택 상태로 전환한다. 전장·광산·광장을 이동하고 자원을 볼 수 있다. 화면 전환은 기존 페이드/슬라이드·동작 줄이기 설정을 따른다.
- 관전 중 UI 조작과 명령 큐 진입을 차단한다. 서버는 인증된 자기 참가자만 명령 주체로 사용하고, 관전 중 명령과 참가자 식별자 덮어쓰기를 거절한다. 나와 선택 상대 한 명만 전체 게임 상태를 보내며 나머지는 요약이다. 계정 키·토큰은 관전 데이터에 포함하지 않는다.
- 재연결 시 선택 관전을 다시 구독한다. 자기 상태와 관전 상태의 HUD·장면 선택·피해 연출을 구분했다. 패배 후에도 관전 화면을 이동할 수 있도록 분기했다.
- 배속 쿨타임은 12시부터 시계 방향으로 비워지는 원형 부채꼴이다. 5초 제한은 유지한다. 첨부 그림의 동작 방향을 반영했다.
- 타이틀 행인의 경로가 성벽 위까지 이어지던 것을 성문 안에서 끝내도록 수정했다. 머리만 뒤집던 처리를 몸 전체 방향 전환으로 바꾸고 말과 마부가 같은 길을 따르게 했다.

## 검사 결과와 미완료

17개 자동 검사 묶음, 최종 Sites 빌드, 격리 workerd HTTP/DB 검사 통과. 실제 로컬 2인/4인 WebSocket·재접속·중복 명령·관전 범위·독립 웨이브 검사 통과. 새 검사는 4인 상한, 지역 배정/저장, 관전 데이터 필터링, 서버 조작 거부, 클라이언트 자기 상태 보존·조작 차단·복귀와 행인 경로를 포함한다.

**실제 브라우저 시각 검증은 미완료다.** Edge 제어 연결이 없었고 내장 브라우저는 webview 연결 대기에서 실패했다. 이후 Windows 브라우저 제어도 현재 URL을 확실히 판별하지 못해 도구가 현재 턴의 Computer Use를 중단했다. 이를 우회하지 않았고 이번 변경의 브라우저 스크린샷을 만들었다고 표시하지 않는다. 타이틀·지도·세 지역의 실제 레이아웃, 배속 애니메이션과 행인 방향은 브라우저 연결 복구 후 확인해야 한다. 로컬 미리보기 주소는 http://127.0.0.1:8791/game/ 이다.

브라우저 복구 후 4인 로컬 방을 만들고 다른 지역 선택 → 전장/광산/광장 → 내 국경 복귀 → 재연결을 확인한다. 실제 클릭·키보드·명령 우회 검사와 양쪽 재화/포탑 불변 확인, 1366×768 / 390×844 / 844×390 배치, 쿨타임 중간 프레임과 행인의 성문 통과를 캡처한다. 그 뒤 디자인/배포 승인을 받는다.

## 관전 지연 분석

기존 클라이언트는 내 전장 RAF와 별도 관전 RAF가 동시에 렌더링했다. 관전에서는 매 프레임 상태 정규화와 통계 DOM 갱신까지 했다. 새 코드는 선택 지역만 주 캔버스에 그리며 상태 정규화는 스냅샷 수신 시 한 번 한다. 서버 delta도 각 재귀 단계에서 전체 하위 트리를 JSON 문자열로 비교하던 중복 작업을 제거했다.

로컬 Node 합성 측정(4명, 각 적 160·포탑 30, 60회)에서 관전 스냅샷은 39,016B, 자기 상태만은 20,182B였다. 관전 delta 처리 중앙값은 기존 3.0226ms → 변경 0.3088ms, p95는 4.2591ms → 0.6124ms였다. 약 9.79배 수치는 이 합성 delta 함수 비교에만 해당한다. 측정 파일은 spectator-delta-benchmark.json이다.

실제 브라우저 FPS·사용자가 느끼는 지연·운영 Worker CPU/한도는 이 수치로 입증하지 않았다. 후반 웨이브 동일 상태에서 내 화면/관전 각각 10~15초의 draw 시간·RAF p95·50ms 이상 프레임·수신 bytes/s·지역 선택 첫 프레임 시간을 측정해야 한다. 네트워크 ping, 서버 시뮬레이션/방송/체크포인트 지표를 분리하고 여러 번 전환해 캔버스/RAF/리스너가 증가하지 않는지도 확인한다.

## 배포 시 주의

프런트와 별도 PvP Worker 모두 바뀐다. 승인 후 기존 바인딩·DB/DO·secret을 보존해 백엔드를 먼저, 같은 프로토콜의 프런트를 뒤에 배포한다. 이번 변경은 schema/class migration이 없다. 새 가입·도메인·DB를 만들지 않는다. 도구 run-capacity.mjs는 실제 배포/원격 migration/secret/도메인 변경을 하는 운영 도구여서 이번 로컬 검사에서 실행하지 않았다.
